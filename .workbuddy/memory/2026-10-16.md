## 新 mod：TX-41 灭菌器 伤害 → G-4 毒气榴弹级别（v1.0.0）

用户需求原话：**"TX-41 灭菌器 的喷毒射程范围更改为和 B/FLAM-80 焚燃者 喷火范围一样，

### 结论：伤害做到了，**射程做不到**（数据层没有这个字段）

**离线排查路径**（全部记进 MEMORY #25）：

1. 从本地化表反查：`Sterilizer`=entity `9869105320050739364`，`Torcher`=entity `5742363029208942635`
   （两个都有 `SprayWeaponComponentData` —— 喷射武器专用组件）。
2. `SprayWeaponComponent.projectile_type = ProjectileType_None`
   ⇒ 喷射武器**不发射射弹**，伤害靠**粒子碰撞事件**触发 component 里的 `damage_info_type`。
3. 翻遍所有可能有"射程"的地方，**全部为空**：
   * `SprayWeaponComponent`（typelib: 224B / 16 成员；社区 JSON 同样 16 字段）—— 无 range/length/distance；
   * `WeaponDataComponent` 56 个字段 —— 无；

   * `BeamSettings` 14 条 beam —— 只有 Small/Medium/Large/LaserCannon/BotTorch… 没有化学/火焰喷流；
   * `CollisionEventSettings` / `StatusEffectSettings`(59 项 + 28 模板) —— 都没有范围；
   * 用 `grep` 把 `components/*.json` 里所有含 range/length/distance 的组件列了一遍 —— 无一个是喷射武器会用的。
4. 而且这些都是 `*ComponentData` ⇒ 内存里不加载（硬约定 #17）。
⇒ **射程由枪口粒子效果（muzzle_effect，VFX 资源哈希）决定，Lua 内存补丁改不到。**
   （备选替代：改伤害/毒气效果强度，已在交付说明里给用户列了选项。）

## 下午：灭菌器 v2.0.0 —— "毒气强度/持续时间调强"的唯一可行路径

用户原话："射程改不了那把毒气效果的强度/持续时间调强"。

### 离线摸清的事实（都有证据）

* 灭菌器喷中的目标挂两个状态效果（**离线从 `generated_damage_settings.json` 读到的名字**）：
  `StatusEffectType_Gas`（毒气，带 `DamageInfoType_DPS_Gas` 掉血）+ `StatusEffectType_Gas_Confusion`（致幻）。
  记录里 SE 字段是 `type=43 / 45`、`value=0.5`。
* 这两个效果的 `strength`/`duration` 在**全局表 `StatusEffectSettings`（类型哈希 `0xC63E0B22`）**：
  `Gas: strength 0.25 / duration 6`、`Gas_Confusion: strength 0.25 / duration 5`。
  **共用者 = 灭菌器 + 敌方化学无人机 + G-4 毒气榴弹 + 轨道毒气弹 + 胚胎簇**。
  ⇒ 改它 = 敌我一起变强。
* **`StatusEffectInfo` = 152 字节**（typelib 权威）。用**类型哈希反查**确认了三个字段：
  `m0@0 = StatusEffectType`（枚举，哈希 1381927827）、`m2@16 = StatusEffectShaderVariablePreset`、
  `m7@44 = DamageInfoType`（哈希 970127245）—— 与社区 json 的字段顺序**逐一吻合**，
  故 `fade_time@32 / strength@36 / duration@40 / damage_info_type@44` 可信。
* `parse_typelib.py` 跑出来 `strsize=0` ⇒ **dl_typelib 里没有成员名/枚举名**，只能靠哈希 + 社区 json 对齐。
* ⚠️ **社区两个 JSON 自相矛盾**：`enums/StatusEffectType.json` 说 43=Gas_Confusion、44=Gas_MK2；
  而 `status_effect_settings.json` 的 items 顺序是 Gas, Gas_MK2, Gas_Confusion。
  ⇒ **绝不能用枚举序位推名字**（又一次印证硬约定 #1）。

### 用户拍板 & 实现

用 AskUserQuestion 问了两件事，用户答：**「仅灭菌器」** + **「原版 2 倍即可」**。

⇒ 做成：改 `DamageSettings` 里**灭菌器自己那条记录**的两个 SE 施加量
  `+48 SE[Gas].value` / `+56 SE[Gas_Confusion].value`：**0.5 → 1.0**。
  **"持续时间"放弃**（只在全局表里，没有 per-weapon 入口；改它会把敌人一起强化）。

`src/sterilizer_gas_damage.lua` → **v2.0.0**（同资源名 / 同 GUID，覆盖安装）。

### 关键设计点

1. **指纹收紧（v2.0.0 的核心改动）**：旧指纹含 `SE value == 0.5`，而 v2.0.0 要改 value ⇒
   打完 / cfg 热调后**认不出自己**。新指纹改为
   「`AP=[5,5,5,0]` + `demo=5` + `force=10/5` + **前两条 SE 的 type ≠ 0** + 后两条 SE type == 0 + `damage∈[1,200]`」
   ——**完全不引用本 mod 会改的字段**。离线核对：在真实 649 条整表上**仍恰好命中 2 条**。
   ⇒ 新增单测 **T17**（稳态热调 cfg：3/1.0 → 7/3.5，必须重打且 `patched_records` 仍为 1）守着。
2. **`+52..+55`（SE[1].type）是毒气值之间的"空隙"** ⇒ 两次**独立 4 字节写**，中间绝不触碰。
   T2 有专门断言 `52 not in diff`。
3. **纯 Lua `f32_bits()` 打包 float32** —— LuaJIT 无 `string.pack`，离线 harness 的 ffi 也是假的。
   加了往返 self-test（0.5/1.0/3.0/6.0/0.25…）。
4. **cfg 升级为双参数**：`damage=3` / `gas=1.000`；**兼容旧版**（整个文件一个裸数字 = damage）。
   解析按行、跳过 `#` 注释行。
5. **顺手修掉一个 v1.0.0 的真 bug**：`recheck()` 里引用了**未定义**的 `CONFIG.REC_SIZE`
   ⇒ `read_mem(addr, nil)` → 比较 nil 会报错 → **稳态复查一直失败（cfg 热调从来没生效过）**。已补 `REC_SIZE = 76`。

### 踩坑（给下次）

* **变异测试打不过 `recheck` 的兜底**：一开始把变异做成"`patch_into_table` 里跳过写"，
